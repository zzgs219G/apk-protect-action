# 报错速查(AI 排障第一入口)

> 本表是 `docs/流程文档.md` §5 的独立版:报错现象 → 根因结论 → 修法。
> **完整根因分析、推理链、验证过程在 [变更历史.md](./变更历史.md) 对应条目**,本表只留结论。
> 新增报错时的同步规矩(三处):① 本表加一行;② 变更历史加全文;③ 流程文档 §5 若有引用则同步链接。

## 通用环境/依赖类

| 报错现象 | 根因 | 修法 |
|---|---|---|
| `ModuleNotFoundError: asn1crypto` | pip 依赖未装 | `pip3 install -r sigcheck/dex2c/dcc/requirements.txt`(workflow 已内置) |
| `file app.apk is not exists` + "工程包不存在" | IN_APK 相对路径,`cd $DCC_DIR` 后失效 | 脚本开头绝对路径规范化(已修);审查新脚本是否有同模式 |
| `unzip ... cannot create extraction directory: build/dcc` | workflow 直跑 unzip 时 `build/` 父目录不存在(unzip 不自建多级父目录) | 解压步骤前 `mkdir -p`(已修) |
| NDK 编译 `incompatible integer to pointer conversion ... 'jobject' from 'int'` | runner 预装 NDK r27 抢位且未校验版本,clang 18 把 dcc 生成代码的整数赋指针从 warning 升级为 error | `setup-ndk` action 候选循环加版本校验(已修);教训:"优先预装"必须校验版本 |
| 机器上只编出 v7a | Application.mk 被覆盖/未生效 | 联合方案必须 `armeabi-v7a arm64-v8a` 双 ABI |
| ndk-build 报 JNI_OnLoad 重复 | 有人把 sig_check 改成了 JNI_OnLoad | 保持 `__attribute__((constructor))` 入口 |
| 报错三十六:`未知参数: schema_rules/lightobf.txt`(轻量混淆勾选,加固启动即炸) | `resolve-config.py` 输出 `--light-obf/--flags/dba/规则路径` 四行,规则路径被 `--flags` 隔开;`protect.sh` 的 `--light-obf` 分支只收紧邻 token,`--flags` 分支注释称"位置不限"却没兜住规则路径 → 路径孤立落入 `*)` 分支 | `protect.sh` `--flags` 分支收纳 flags 值后追加收纳紧随其后的规则路径(已修);教训:**"位置不限"的参数顺序承诺必须有消费端测试兑现;两端契约要在真实链路上做集成验证** |

## Manifest/解包/灰包类

| 报错现象 | 根因 | 修法 |
|---|---|---|
| 产物"灰包":MT/文件管理器不认、无法安装(报错五) | `-r` 解包出文本 Manifest,回编时被原样拷回(不重编 AXML)→ PackageParser 拒识 | 解包去掉 `--force-manifest`,Manifest 全程保持二进制;extractNativeLibs 用 `patch-extractnativelibs.py` 原位改写(已修) |
| `未从 AndroidManifest.xml 找到 LAUNCHER activity` | `inject-loadlib.py` 两条解析路径都失败 | 确认 `_DCC_DIR` 对、androguard 可导入(报错五修复后 Manifest 是二进制,走 AXMLPrinter 分支) |
| 报错六:`androguard 不可用...No module named 'lxml'` + `未找到 LAUNCHER activity`(仅云端) | 新建 workflow 漏抄 python 依赖安装步骤 → AXMLPrinter 导入失败 → 降级文本正则必失败 | workflow 补 `pip3 install -r .../requirements.txt`(已修);教训:**二进制 AXML 场景下降级=必失败** |
| `inject-loadlib.py` 多 dex 大包 `<类名>: missing`(报错七) | 正则 `r'\d'` 被写成 `r'\\d'`(双重转义),静默只命中裸 `smali/` 目录 | 改回 `^smali(?:_classes\d+)?$`(已修);`mark-native.py` 复用同一正则同受影响 |

## dcc/dex2c 类

| 报错现象 | 根因 | 修法 |
|---|---|---|
| 工程包不存在但 dcc 无报错 | filter 未命中(类名写错/格式错) | 按 流程文档 §4.1 核对 full_name:无 `->`、类名是斜杠 |
| 报错九:`no compiled methods`(仅多 dex 包) | dcc 原版只读 `classes.dex`,目标类在 classes2+ 必 0 命中,dcc 静默 return | `dcc.py` 已加 `auto_vm_all()` 多 dex 支持(已修) |
| `UnsatisfiedLinkError`(报错十三同型) | mk 模板只收一级 `jni/*.cpp`,源码在 `jni/nc/` 子目录 → 空壳 so | `lib-ndk.sh` 双级 wildcard(已修);**新 mk 必须覆盖所有实际源码布局** |
| `mark-native.py` exit 3 | 方法没在 smali 中找到 | 查多 dex 目录遍历;查混淆改名 |
| 签名校验总是失败 | 重签 keystore 与指纹不一致 | `sig_hash.h` 指纹必须来自**最终发布** keystore |
| 报错十四/十七:签名一致仍"apk not found"/延时 abort | `find_apk_path` maps 分支被包名中 `.so` 子串误命中/整行前缀当路径;Android 11+ `/data/app` 不可列 | 已修:so 路径反推 + base.apk 行取纯路径 + `access(R_OK)` 验证;教训:**子串匹配要防"匹配到路径中非目标段"** |

## 字符串加密类

| 报错现象 | 根因 | 修法 |
|---|---|---|
| 字符串加密 0 命中(规则明明写了 `**`) | 喂了 rules-to-filter 的产物(dcc 正则)而非用户规则 → 二次转换产生畸形正则 | 直接把**用户规则文件**交给 `encrypt-strings.py`(已修) |
| 字段的字符串值仍是明文 | R8 把 `static final String = "x"` 折叠成注解形态,不是 `const-string` | 本模块已含 field 分支;若仍明文查类是否被硬排除/`!` 排除 |
| 报错"没有任何字符串被加密" | 规则只命中系统类/依赖类(被硬排除),或规则格式错 | 看"被硬排除跳过: N 个类"日志;确认规则是点号通配符格式 |
| 桩汇编 `Invalid register: vNN. Must be between v0 and v15` | 桩 `.registers` 过大 → 参数 p0 落 v18;`array-length` 等是 12x 格式上限 v15 | 桩 `.registers` 收窄到 16(已修) |
| 报错二十一:回编 `Invalid register: vNN`(大方法/Compose) | 注入的 `invoke-static` 复用 8 位寄存器号,const-string 是 21c 而 invoke 是 35c(上限 v15) | 注入改 `invoke-static/range`(已修);`_PAYLOAD_RE` 同步放宽,防 keystream 复用 |
| 报错二十七:`StrDec.smali ... mismatched input` | 种子注入替换范围越界把桩骨架腰斩;终检按行数比较退化失效 | 整行重建+止于行尾(已修);终检改按值对比+骨架行数守恒断言;**文本断言绿≠结构合法** |

## anti-diff 类

| 报错现象 | 根因 | 修法 |
|---|---|---|
| 报错三十一:回编 `no viable alternative at input 'const/4'` | E 生成的标签定义行带尾冒号(`:ncXX:`)且下一行是指令 → smali 解析炸 | 标签定义行去尾冒号(已修);教训:**宽容编译器要看 token 组合,必须真实包全量回编闭环** |
| 报错三十二:ART VerifyError 闪退 | 变换 C 插 `move v,v` 自赋值读未初始化寄存器 | 移除 move 形态,只用 `const/4` 纯写(已修) |
| 报错三十三:寄存器置换越界回编炸 | 4-bit 编码上限 v15、/range 连续性约束 | 越界锁定不置换(已修) |
| 报错三十四:`TaskEntity.smali Invalid register: v16` | C0 提升 `.locals` 时参数物理号整体 +4,多参数槽方法 pN 超 v15 | `_bump_locals` 按签名数参数槽(J/D 计 2),`4+槽-1>15` 不提升(已修) |
| 报错三十五:anti-diff 产物闪退(回编通过,dex 层非法) | 变换 D 的 wide 寄存器对被拆散(`move-result-wide`/`cmp*-double`/invoke 宽参数漏保护) | 三处同源漏洞全修 + `_collect_invoke_wide_pairs` 按被调签名定位(已修);教训:**wide 两寄存器是不可拆整体;回编通过≠dex 合法** |
| 报错二十二:三变换"全部无效"且字符串被误改 | 真实包往返验证发现变换不落 dex + 误改字符串 | 往返断言修复(见变更历史全文) |

## 回编/格式保真类

| 报错现象 | 根因 | 修法 |
|---|---|---|
| 报错八:注入后 APK 膨胀 380KB~1.8MB | apktool 回编重建 debug_info,按方法数线性放大 | 解包加 `--no-debug-info`(已修);排"包变大"先对比 dex map 区块 |
| 报错十八:Compose 首帧 `IncompatibleClassChangeError` | apktool 回编一律写 035 头,原包 038 的接口方法按旧规则校验 → ICCE | `patch-dex-version.py` save/restore 双模式(已修);教训:**"两包内容一致却一崩一不崩"先 diff 字节级元数据** |
