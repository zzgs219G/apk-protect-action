# anti-diff 体积增量归因实测报告(2026-10-17)

> 本文为**实测档案**,只记录"防对比模块体积增量"的量化结果,不记录任何代码改动。
> 写作时的仓库 HEAD:`131b1bb fix(javalink): 心跳喂食前置于测量链——修正常包冷启动被误杀(报错四十九)`。
> 所有数字均为**回编后逐字节实测**,非理论推算。

## 0. 结论速览(TL;DR)

- anti-diff 让 APK 涨 **+70,724 字节(1.5%)**,dex 涨 **+74,316 字节(1.05%)**。
- 增量 **~80% 来自 E(条件反折)和 C(return 前插桩)两个变换**——它们往方法体里
  塞的是**真指令**,会真进 dex;其余 ~15KB 是两变换同时开启时的交互效应。
- 其余变换(A 标签重命名 / B 块重排 / C0 .locals 提升 / D 寄存器置换 / F 等长重编码)
  对 dex 字节**零贡献**(实测均 +0),只有 F 设计上就是"等长零膨胀"。
- **不是 bug,是设计必然**:要防对比,噪声必须真进 dex;要真进 dex 就必然占字节。
- 流水线两处**小问题**(已实测复现,未修改):`--max-cond-flip 0` 会崩且留脏状态、
  `--max-per-method` 已是死参数。

| 项 | 值 |

| 解包方式 | `java -jar apktool.jar d -r -f --no-debug-info -o <目录> base.apk`(`lib-repack.sh:42` 同款) |

## 2. 总量:anti-diff 实际涨了多少

| 阶段 | APK 字节 | classes.dex 字节 |
|---|---|---|
| 解包后原样回编(基线) | 4,713,928 | 7,079,316 |
| anti-diff 处理后回编 | 4,784,652 | 7,153,632 |
| **增量** | **+70,724(1.50%)** | **+74,316(1.05%)** |

> **4.563 MiB 与用户报的"4.56mb"完全吻合**(4,784,652 ÷ 1,048,576 = 4.563)。
> 用户报的增量 `4.45 → 4.56 = +0.11 MiB ≈ 115KB`,比本次隔离实测的 +70KB 大约
> 45KB——多出的部分**不属于 anti-diff**,是 apktool 解包/回编的基线开销。
> 需要用户提供"4.45"那个具体文件路径才能精确归因,本文仅确认 anti-diff 的
> 自身贡献为 ~70KB/1.5%。

## 3. 逐变换归因(回编后 dex 字节)

做法:把 `anti-diff.py` 以模块方式加载,按变量**逐个关掉其他变换只留一个**,
回编后取 `classes.dex` 字节数,与基线相减。

| 配置 | dex 字节 | 对比基线 |
|---|---|---|
| 基线(未跑 anti-diff) | 7,079,316 | — |
| **仅 E**(条件反折) | 7,114,248 | **+34,932** |
| **仅 C**(return 前插桩) | 7,103,812 | **+24,496** |
| 仅 F(等长重编码) | 7,079,316 | **+0** |
| 全开(= 实际流水线) | 7,153,632 | +74,316 |

**E + C ≈ +59,428,占全量增量 74,316 的 80%;剩余 ~15KB 来自"两个变换同时
开启"的交互效应**(C0 提升 `.locals` 后 C/D 覆盖到更多方法,插桩落点变多)。

### 3.1 零字节变换的确认

对 A/B/C0/D/F 各自单独启用,回编后 dex 与基线**逐字节相同**:

| 变换 | dex 增量 | 原因 |
|---|---|---|
| A 标签重命名 | 0 | 标签只是 baksmali 的临时符号,dex 里是偏移量,重命名不改字节 |
| B 类内块重排 | 0 | 方法/字段块位置对 dex 无意义(method_ids 不记源码顺序) |
| C0 `.locals` 0→4 提升 | 0 | `registers_size` 是 code_item 的 u16 字段,提升不增字节;但它**间接**让 C/D 覆盖到原本没有局部寄存器的方法 |
| D 局部寄存器置换 | 0 | 只重编号,不增删指令 |
| F shl⇄mul 等长重编码 | 0 | 22b 格式 4 字节等长,设计目标就是零膨胀 |

> 这与 README 里"报错二十二教训"一致:变换 A/B 在 dex 层完全无效,
> **真正落进 dex 的只有 C+/E/D/F**;其中 D/F 又不增字节,所以体积全部由 C+ 和 E 出。

## 4. 为什么这两条"必然"占字节(设计机制,不是浪费)

### 4.1 变换 C+ —— `anti-diff.py:649-716`

每个 `return` 前**固定插 1 条** `const/4 v0..v3, 0x0/0x1`(`_insert_before_returns`
定义在 `anti-diff.py:649`,调用点 `anti-diff.py:1322` 传第 4 参 `1` 硬编码)。
`const/4` 是 1 个 code unit = 2 字节。

本包共 53,133 条 `return*` 指令,但不是每处都能插:方法须 `.locals ≥ 4`
(不足的先被 C0 提到 4 才有资格)、不得含 try-catch、非 native、非
`<init>/<clinit>`,且 `const/4` 只能写 v0..v3、还要排除 return 读取的寄存器。
**实测仅 C 时 dex +24,496 字节 ≈ 12,415 处实际插桩 × ~2 字节**——即全量 return
里只有约 23% 落进了插桩,其余被门槛挡住。

### 4.2 变换 E —— `anti-diff.py:588-648`

每处可反折的 `if-eqz vX, :L` 改写成 3 行:

```
if-nez vX, :ncXXXXXX      ← 原指令被替换(等长)
goto :L                   ← 新增 1 条真实指令
:ncXXXXXX                 ← 新标签定义(非指令,不占 dex)
```

净增 1 条 `goto`。流水线未传 `--max-cond-flip`,用默认 **3**(每方法最多 3 处)。
**实测仅 E 时 dex +34,932 字节 ≈ 17,205 次反折 × ~2 字节/goto**——全包可反折的
条件分支远不止这些,实际只反折了其中一小部分(受"每方法 ≤3 处"与 fall-through
排除规则限制)。

**这条是"真实多 1 条 goto 落 dex"——README/流程文档 §3.8 都明文写了**,它是
"让 MT 的 diff 全红"的核心手段之一,不是溢出。

### 4.3 一条关键对照:为什么不能"砍掉 E/C 就省字节"

MT 对比按用户配置会忽略:编译优化 / 寄存器数量 / 调试信息 / nop。
变换 A/B/D 恰好落在会被忽略的维度里,**回编→再反编译后 100% 复原**;
只有 C+/E/D/F 的真实指令能穿透这些忽略项。所以"省字节"的代价直接等价于
"降低防对比强度",没有免费的压缩空间——F 是唯一零损耗的真实变换。

## 5. 顺带发现的两处流水线问题(实测复现,**未修改**)

### 5.1 `--max-cond-flip 0` 会让脚本崩溃且 exit 0

```
$ python3 anti-diff.py <目录> --max-per-method 1 --max-cond-flip 0
  n_flip = min(len(candidates), rng.randint(1, max_per_method))
ValueError: empty range in randint(1, 0)
```

- 位置:`_invert_conditionals`,`anti-diff.py:612`;
- `randint(1, 0)` 抛 `ValueError`,异常沿 `process_file` 冒出 `main`,实测
  **真实 exit code = 1**(此前误记 0,是管道里 `tail` 的退出码);
- **会留下脏状态**:崩溃前已处理完的文件**不回滚**——实测本次在崩溃点之前
  已有 2 个类被打上 `nc-antidiff-applied` 标记并改写;重跑会因标记幂等跳过,
  得到一个"只处理了一部分类"的半成品目录且脚本表现为成功;
- **流水线不受影响**(`protect.sh:441` 未传该参数,用默认 3),仅 CLI 直跑时
  的边界问题。

### 5.2 `--max-per-method` 已是死参数

- `--max-per-method` 只被 `_inject_junk_at_entry` 消费,而该函数的调用点已在
  `anti-diff.py:1332` **注释下线**(用户拍板 2026-09:入口插桩砍掉);
- 实测:`--max-per-method 3` 与 `--max-per-method 1` 跑出的 smali 行数**完全相同**
  (都是 2,685,074),证明该参数无任何效果;
- 但 `anti-diff.py:1418` 的 CLI 帮助文本仍写"变换 C 单方法/单 return 最多插入
  条数(默认 3)",`--level 1` 的说明同样过时,**具有误导性**。

## 6. 可用的降体积旋钮(如需,未动)

| 旋钮 | 现状 | 改法 | 预估省 |
|---|---|---|---|
| E 反折上限 | `--max-cond-flip` 默认 3,流水线未传 | 传 `1` | ~2/3 的 E 增量 ≈ 23KB |
| C+ 每处条数 | 硬编码 `1`(`anti-diff.py:1322`) | 需改代码(本报告不改动) | 再省 C 的一半 |
| C0 覆盖面 | `.locals<4` 提升到 4 | 关掉会**同时损失 C/D 的覆盖率**,不建议 | — |
| F | 零膨胀 | 不需要动 | — |

> 提醒:`--max-cond-flip` 降为 1 会减少落进 dex 的真实指令密度,防对比强度
> 相应下降,需要用"回编→再反编译→MT 对比往返"重新验收(README 报错二十二
> 教训:smali 文本 diff 全红不算数)。

---

## 7. 结论

1. anti-diff 在本包上的真实体积代价是 **APK +70KB / dex +74KB(约 1.5% / 1.05%)**,
   与"4.56 MiB"的实测值吻合;
2. 增量 **80% 来自 E+C 两个变换**,是"噪声必须真进 dex"的设计必然,**无 bug、
   无浪费**;
3. A/B/C0/D 对 dex 字节零贡献,F 是唯一的零损耗真实变换;
4. 流水线有两处 CLI 边界问题(`--max-cond-flip 0` 崩、`--max-per-method` 死参)
   需要后续处理,但不影响现有产物;
5. 若要压体积,唯一有意义的旋钮是 `--max-cond-flip`,且必须重新做真机对比验收。
