# 简盒 正式版 vs 加壳版 对比测试报告

- **测试日期**：2026-10-12
- **设备**：Xiaomi 2602BRT18C / Android 16 / SDK 36
- **测试对象**：
  - 正式版：`简盒-正式版-v2.1.1_211-20261011-2048-18f9281_sign.apk`
  - 加壳版：`简盒_加壳.apk`
- **包名 / 主 Activity**：`com.xixin.box` / `.MainActivity`（两版相同，覆盖安装）
- **方法**：同一台设备、同一脚本、同一时段；`am force-stop` 后 `am start -W` 取 `TotalTime`

---

## 一、结论摘要

| 维度 | 结论 |
|---|---|
| 冷启动 | 加壳版慢 **约 2.2 倍**（427ms vs 195ms），多约 230ms |
| 启动 CPU | 加壳版多耗 **约 1.2s（+43%）** |
| 内存 PSS | 加壳版多占 **约 59MB（+21%）** |
| 热启动 | 两版均测不出（`TotalTime=0`，失真值） |
| 崩溃 | **与加壳无关**，正式版同样复现，系应用自身缺陷 |

## 二、性能对比

### 2.1 冷启动（`am force-stop` 后 `am start -W`）

| 轮次 | 正式版 | 加壳版 |
|---|---|---|
| 1 | 271ms | 603ms |
| 2 | 180ms | 412ms |
| 3 | 195ms | 447ms |
| 4 | 195ms | 427ms |
| 5 | 201ms | 423ms |
| **稳态中位数** | **~195ms** | **~427ms** |

> 首轮两版都偏高（271 / 603ms），属首次启动额外开销，加壳版同样翻倍。

### 2.2 启动阶段 CPU 占用

进程启动后 6 秒内 `/proc/<pid>/stat` 累计 jiffies，HZ=100。

| 轮次 | 正式版 | 加壳版 |
|---|---|---|
| 1 | 2.72s | 3.86s |
| 2 | 2.77s | 3.94s |
| 3 | 2.74s | 3.95s |

### 2.3 内存占用（启动后 8s，PSS）

| 指标 | 正式版 | 加壳版 |
|---|---|---|
| TOTAL PSS | 280.6 MB | 339.9 MB |
| Native Heap | 29.5 MB | 39.3 MB |
| TOTAL RSS | 383.6 MB | 452.1 MB |

### 2.4 热启动

两版 `am start -W` **均稳定返回 `TotalTime=0ms`**，为失真值，不可用于对比。

原因：进程未被真正杀死，Activity 未重建；且 5 次循环中 PID 均变化，说明主 Activity 一启动即交棒，`TotalTime` 只统计到交棒时刻。

### 2.5 数据可信度说明

- **PSS 的 59MB 差距需打折扣**：加壳版进程内常驻 `libnc.so`、`libxixin.so` 与 2.9MB `xixin_data`，属固定成本；正式版数字受系统缓存波动约 ±10MB，但差距超出噪声范围。
- 加壳代价集中在**冷启动**与**启动 CPU**，运行期稳态差异无法用 `am start -W` 测出。

## 四、崩溃复现与归因

### 4.1 崩溃文件记录

目录：`/sdcard/Android/data/com.xixin.box/files/crash_logs/`

| 时间戳 | 当时安装的版本 | 触发方式 |
|---|---|---|
| 20:41:17 / :28 / :39 / :50 / 20:42:01 | 加壳版 | 手动测试（间隔 11s） |
| 20:43:38 / :49 / 20:44:00 / :11 / :22 | 正式版（20:43:13 换装） | 手动测试（间隔 11s） |
| 20:55:52、20:56:04 | 加壳版 | 脚本复现 |
| 20:57:04 | 正式版 | 脚本复现（同一脚本） |

### 4.2 触发条件对照

| 操作 | 结果 |
|---|---|
| 纯冷启动 ×8（force-stop → start） | **0 崩溃** |
| 反复 force-stop 重启 | 0 崩溃 |
| HOME 回桌面再打开 ×25 | 0 崩溃 |
| **进程存活 + BACK 销毁 Activity + 重新启动** | **稳定复现** |

### 4.3 异常堆栈

```
java.lang.IllegalStateException: State must be at least 'CREATED'
  to be moved to 'DESTROYED' in component e23(<uuid>)
  destination=ag0(0x3fd384b5) route=com.xixin.box.navigation.MainHubRoute

fk2.e → e23.h → c33.t → c33.b → c33.k → c33.l → i.invoke
→ t21.invoke → ah4.invokeSuspend → hu.resumeWith → p01.run → rd.t0
```

- 两版堆栈**逐帧一致**，仅 `component e23(...)` 的 UUID 每次不同。
- 正式版带 R8 行号映射（`r8-map-id-...:70`），加壳版显示 `Unknown Source` —— 证明二者为**同一份 dex 代码**。
- 崩溃前应用日志固定末行：`[Splash] ✅ 配置已是最新，无需更新`

### 4.4 根因

- `SplashViewModel.kt:27-36` 时序：`REVEAL_MS(1000) + DRAIN_SECONDS(3) + POST_DRAIN_DELAY_MS(80) ≈ 4s`，与实测崩溃时机吻合。
- `SplashScreen.kt:102-122`：倒计时协程的 **`finally` 块无条件调用 `navigateOnce()`**。协程因 composition dispose 被取消时，`finally` 照样执行。
- `AppNavHost.kt:78`：`navigate(MainHubRoute){ popUpTo(SplashRoute){ inclusive = true } }`

Activity 销毁途中仍执行 `navigate()`，新建的 `NavBackStackEntry` 停在 `INITIALIZED` 就直奔 `DESTROYED`，抛出异常。

> **结论：该崩溃是应用自身的 Jetpack Navigation 竞态缺陷，与是否加壳无关。**

## 五、修复方案（已实施）

涉及文件：

- `jian_box/app/src/main/java/com/xixin/box/page/splash/SplashScreen.kt`
- `jian_box/app/src/main/java/com/xixin/box/navigation/AppNavHost.kt`

| # | 改动 | 说明 |
|---|---|---|
| 1 | `navigateOnce()` 移出 `finally`，仅保留在正常走完的路径上 | 取消时 `animateTo`/`delay` 抛 `CancellationException`，协程直接退出，不再导航 |
| 2 | `hasNavigated` 由 `rememberSaveable` 改为 `remember` | 避免 Activity 重建后标志仍为 `true`，导致永久挡掉导航、卡在启动页 |
| 3 | `AppNavHost.kt` 导航前加生命周期守卫 | `lifecycleOwner.lifecycle.currentState.isAtLeast(Lifecycle.State.CREATED)` 为真才导航 |
| 4 | 清理失效 import | 移除 `rememberSaveable`、`kotlinx.coroutines.isActive` |

**对"点跳过"的影响**：无。`onSkip`（`SplashScreen.kt:255-261`）直接调用 `onAnimationEnd()`，不经过 `navigateOnce()`，三条改动均不触及该链路。
