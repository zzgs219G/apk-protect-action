## 1. P2-1：JNI 符号面（收益最大）

### 1.1 原来泄露什么

报告实测 `nm -D` 一条命令的结果：

```
Java_com_nc_link_NcLink_ncVerify                        152 B
Java_com_nc_link_NcLink_heartbeat                       136 B
Java_com_nc_link_NcLink_selftest                          ? B
Java_amimo_dcc_DccApplication_init__                      4 B
Java_com_xixin_box_MainActivity_k__...                21692 B   ← 业务复杂度地图
Java_com_xixin_box_MainActivity_onCreate__...          5460 B
Java_com_xixin_box_MainActivity_onConfigurationChanged__...  1084 B
```

**`21692 B` 这个数字本身就是情报**：不用解密就知道哪个方法最复杂、业务
重心在哪。加密层保护了代码内容，却把地图摊开放在门口。

### 1.2 为什么 `-fvisibility=hidden` 没用

`JNIEXPORT` 自带 `visibility("default")`——JNI 短名绑定要求函数名必须导出，
ART 才能 `dlsym` 找到。所以编译器的 hidden 对它们无效。

### 1.3 改法：动态注册

```
编译期：-DJava_xxx=ncg_d2c_<n>   把实现函数改名
        visibility("hidden")      保证不出 .dynsym
        RegisterNatives 表         以字符串写方法名/签名（运行期用）
链接期：--version-script=hide.map   .dynsym 只导出 JNI_OnLoad
```

三个关键设计：

- [ ] **用 `visibility("hidden")` 而非 `static`**：static 无法跨文件取地址，
      而 `RegisterNatives` 正需要函数指针。hidden 保证不进 `.dynsym`，
      链接期仍可被注册器引用（实测 `nm -D` 查不到、`nm` 是本地符号 `t`）
- [ ] **签名必须来自 `compiled_methods.txt`**：C 侧参数全被转成 `jobject`，
      从参数推导只能得到 `Ljava/lang/Object;`，与真实签名不符 →
      `RegisterNatives` 必然失败。这份方法表由 dex2c 转译时写出，是唯一准确来源
- [ ] **重载方法走后缀解码**：符号名带 `__Landroid_os_Bundle_2` 时，
      `compiled_methods` 里每个 `(cls,method)` 只有一条，直接用会把所有重载
      写成同一签名。必须按 JNI 规范反转义后缀（`_1`→`_`、`_2`→`;`、`_3`→`[`、`_`→`/`）

### 1.4 新增文件

| 文件 | 作用 |
|---|---|
| `scripts/sigcheck/src/nc_jni_register.c` | 手写入口（selftest/ncVerify/heartbeat）的 `JNI_OnLoad` 注册 |
| `scripts/sigcheck/src/nc_jni_register.h` | 三函数的 `hidden` 声明契约 |
| `scripts/sigcheck/javalink/gen-jni-register.py` | 扫描 dex2c 产物 → 生成 RegisterNatives 表 + 改名宏 |

**性能**：注册只在 `JNI_OnLoad` 做一次（几次字符串比较，微秒级）。
之后 Java→Native 调用走 ART 缓存，与短名绑定无差异。

### 1.5 安全边界（如实）

这不是"不可分析"，而是**消除"一条命令拿全清单"**。攻击者仍可从
`nc_jni_gen.c` 的注册表内容重建映射——但那张表可以后续再加密，
且重建成本远高于 `nm -D`。

## 2. P2-2：`.rodata` 路径密文化

### 2.1 原来泄露什么

`strings` 一遍得到的**完整防御决策树**：

```
/proc/self/status   → 反调试（TracerPid）
/proc/self/maps     → 反注入（frida/xposed 特征）
/proc/net/tcp{,6}   → 反双开 / 虚拟机
/proc/self/task     → 线程级反调试（frida 线程名）
/proc/self/cmdline  → 包名 / 进程身份
/base.apk           → APK 定位（签名校验入口）
APK Sig Block 42    → 直读签名块
```

报告原文：「一条未加密，且不是零散泄漏，是完整算法决策树」。

### 2.2 改法

复用既有 LSGS 机制（构建期 XOR 密文 / 运行期 `lsg_s()` 解码），
与特征串同表。改了 **13 处**：

| 文件 | 处数 | 说明 |
|---|---|---|
| `env_check.c` | 9 | 新增 9 条标记，替换 10 个调用点 |
| `sig_check.c` | 2 | 复用同表（`/proc/self/{cmdline,maps}`） |
| `nc_guard_boot.c` | 2 | **复用 `env_check.c` 的宏**（生成器不扫本文件） |

关键发现：

- [ ] **C 的字符串字面量永远进 `.rodata`，不跟着函数进自定义段**。
      `nc_guard_boot.c` 的函数虽标进 `.ncxhr`，但 `/proc/self/cmdline`
      锁箱后仍能在 `.rodata` strings 出来（实测确认）
- [ ] **注释里禁止书写 LSGS 标记的字面形态**——`/*` 会提前终结注释块，
      编译炸 `top level declarator`（本轮又踩一次，报错速查已有两次记录）

**性能**：路径探针每 20 秒才跑一次，`lsg_decode` 对 20 字节是几十纳秒级，
可忽略。

## 3. P2-3：段名中性化

```
.ncguard → .ncx        .nckey    → .nck
.ncguard_head → .ncxh   .nckey_stub → .ncks
.ncguard_ro → .ncxr     .ncguard_head_ro → .ncxhr
```

**为什么不做完全随机段名**：改名牵动 6 处契约（C 宏、Python 常量、
marker 规则、`.nck` 槽里的地址推导、`.text` CRC 区间、slot 布局），
而收益只是"降低可发现性"（报告给 `★☆☆☆☆`）。**风险与收益不成比例**，
选择只去掉自解释的词，不动结构。

**为什么不用 `.rodata.xxx` 这类伪装名**：实测会被链接器合并回 `.rodata`，
变成 `AX` 段（`.rodata` 不该可执行），反而更可疑。

**同步清单**（改段名必须全改，缺一处即锁箱失败）：

- [ ] `nc_guard_boot.c` 的 6 个 `#define`
- [ ] `so-section-lock.py` 的 `SECTION_NAME`/`SLOT_NAME`/`HEAD_NAME`/`STUB_SLOT`/`HEAD_RO_NAME`
- [ ] `so_section_mark.py` 的 `SECTION`
- [ ] `make-sig-hash.sh` 生成的 `SIG_HASH_SECTION`
- [ ] `env_check.c`/`nc_guard_probe.c`/`nc_link.c`/`sig_check.c` 的段标记
- [ ] `test-so-lock.sh` 的断言

## 5. 本轮踩的坑

| # | 坑 | 教训 |
|---|---|---|
| 1 | `static` 无法跨文件取地址，但 `RegisterNatives` 需要函数指针 | 用 `visibility("hidden")`：既不出 `.dynsym`，又能链接 |
| 2 | 从 C 参数推导 JNI 签名，`jobject` 一律变 `Ljava/lang/Object;` | 签名必须来自 `compiled_methods.txt`（权威来源） |
| 3 | `compiled_methods.txt` 的格式是 `Lcom/a/B;->m(...)V`，正则漏了 `->` | 兼容两种写法：`;-?>` |
| 4 | 手工注册的文件（`nc_link.c` 等）又被扫进生成表 → 重复定义 | `MANUAL_REGISTERED_FILES` 排除 |
| 5 | 注释里写 LSGS 标记字面形态 → 嵌套注释炸编译 | 注释中只描述格式，不写实例 |
| 6 | `.rodata.xxx` 伪装段名被链接器合并回 `.rodata` 且变 `AX` | 伪装名不可行，只能中性名 |
